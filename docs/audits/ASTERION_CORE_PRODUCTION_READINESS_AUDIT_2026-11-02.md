# Asterion Core — Android production-readiness audit (2026-11-02)

**Audited source:** Azrazieliz/Asterion-Core, main at immutable commit **5c5b1573c08ae10ec912b03134bb45a795908046** (v2.0.16).
**Device evidence:** Samsung SM-S948B, Android 17, installed com.ailm.android v2.0.16; ADB observations on 2026-11-02 00:10–00:24 Paris time. No uninstall, data clear, model removal or source relocation was performed.
**Scope:** Android worker, end-to-end AI stages, Qwen llama.cpp, PaddleOCR, ONNX/TFLite, memory manager, SAF/Rounder/TeraBox, SQL/Fusion, review and organization, Compose UI, packaging, tests, and the existing architecture documentation. This is a static code audit with limited independent device observations, not a full production endurance or accuracy test.
**Outcome:** NOT PRODUCTION-READY for autonomous 14,528-image runs, let alone 300,000 images. Significant real implementation exists and must be preserved. The earlier first-stage memory admission failure was not reproduced in v2.0.16, but **no successful end-to-end image was verified** in this run.

## Preserve; do not rebuild

1. Keep Android package com.ailm.android, version-compatible permanent signing certificate SHA-256 4d652e25dfef5d90a3494a993c0e3d60229790d07017297d540c87621508a94e, all existing installed models, private app files and persisted SAF permissions. Update in place only.
2. Preserve the authoritative manually maintained Fusion/Character Knowledge taxonomy, stable IDs, accepted classifications, reference data, imports and user corrections. Never allow AI to rewrite canonical facts.
3. Preserve indexed SQLite keyset pagination (active/imported_order/image_id), incremental scans, durable per-image progress, existing backends and model importers, native Qwen multimodal bridge, review safeguards, and safe copy-verify-commit source-preservation policy.
4. Preserve the separation of **image-specific generated observations** and **canonical character knowledge**. Do not merge repositories or desktop Python and Android app blindly.
5. Never delete originals for possible duplicates, uncertain model routes, missing cloud permissions, or invalid image decoding. Retain source until a verified destination is committed; preserve review and rollback provenance.

## Priority 0 — blockers to functioning automation

**A01 — Inaccessible image URIs and no per-provider recovery [CONFIRMED symptom; cause not yet isolated].** SafStorageProvider.openInputStream is an uninstrumented contentResolver.openInputStream; ImageFingerprinting.inspectStream converts read exceptions/NULL into a generic unreadable result. StandaloneRuntime.automationImagePreflight marks retry_required plus automation_skipped=1. There is no persisted differentiation between grant revoked, provider disconnected, stale document ID, transient timeout, cloud HTTP/auth error, corrupt data or disappearing file. **Modify:** add a non-destructive source-health layer for local SAF, Rounder SAF and direct TeraBox, capture provider/authority and typed error codes, validate persisted permissions and actual open/read, allow targeted document re-resolution/regrant and re-scan only affected roots. Add provider-level circuit breakers and exponential backoff; do not mark unreadable sources complete. **Evidence:** SafStorageProvider.kt:206; ImageFingerprinting.kt:25–67; StandaloneRuntime.kt:1471–1501; observed 18 skips.

**A02 — Rounder cloud staging mismatch [CONFIRMED source mismatch].** SafStorageProvider.walkTree explicitly recognizes authority **com.openlocal.office.terabox.documents**, while StandaloneRuntime.materializeRemoteImageForAi accepts synthetic TeraBox URIs or strings containing **roundsync**. Normal Rounder SAF URIs need not contain roundsync; prepareAiPipelinePayload stages only synthetic TeraBox URIs. In the roundsync-substring path a staged file can exist but image URI fields are not consistently rewritten. **Modify:** centralize source classification by parsed URI authority/provider interface; stage Rounder cloud sources once, pass the staged path to EVERY inference stage and fingerprint, verify bytes, and clean only app-owned temporary copies. Do not duplicate full cloud downloads per stage. **Evidence:** SafStorageProvider.kt:84–88; StandaloneRuntime.kt:1158–1172, 4272–4345; RoundSyncBridge.kt.

**A03 — Background execution is not established on modern Android [CONFIRMED code, UNRESOLVED cancellation].** LibraryAutomationWorker.safeForeground returns immediately for Android 12+ (Build.VERSION_CODES.S), so setForeground and the persistent notification are not used on Android 17. Chaining standard WorkManager one-time tasks is subject to OS scheduling and runtime quotas; actual Asterion job cancellation was observed. **Modify:** implement a standards-compliant user-visible long-running execution mode with appropriately declared service type, explicit user initiation, notification/actions and bounded checkpoints; durable background rescheduling and stop-reason collection. Do **not** assume dataSync foreground services grant unlimited continuous processing or that user-initiated data-transfer jobs are for local ML compute. Use Android 16+ JobScheduler/WorkManager stop reasons and quota diagnostics. **Evidence:** SetupWorkers.kt:395–424; AndroidManifest.xml:5–54; WorkManager chain at SetupWorkers.kt:346–359; JobScheduler device history. Android docs: https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running and https://developer.android.com/about/versions/16/behavior-changes-all.

**A04 — Fragile worker chaining and resumability [CONFIRMED architectural risk].** Worker stores a per-run cursor and returns success after enqueuing APPEND_OR_REPLACE continuation; each run is capped at 32 images/6 minutes. AppViewModel starts using ExistingWorkPolicy.REPLACE; manual reruns cancel an active chain. Stop/pause, process death, device reboot, quota and thermal suspension need integration tests; a JobScheduler cancellation was observed. **Modify:** run-level durable lease/checkpoint state with explicit in-progress image and stage; idempotent restart and atomic next-work scheduling; WorkManager state/stop reason reporting; automatic recovery policy with bounded retries, without user intervention or lost progress. **Evidence:** SetupWorkers.kt:177–389, 441–442; AppViewModel.kt:719–854.

**A05 — In-memory exclusive queue can remain locked if a queued continuation never starts [CONFIRMED code path; occurrence unverified].** A v2.0.16 worker sets automationExclusive=true and intentionally does NOT call resumeAfterAutomation if continuationQueued. If that queued continuation is canceled or left indefinitely waiting without entering the next worker, the same process may keep the global AI scheduler paused indefinitely. The gate is process-local, not a durable ownership lease. **Modify:** lease with run ID, deadline, owner liveness, bounded renewal/recovery and reconciliation; cleanup when WorkManager cancels/stops the unique chain; guarantee scheduler restoration even on enqueue failure or startup interruption. **Evidence:** SetupWorkers.kt:183–189, 345–386; LocalAiRuntimePipeline.kt:2250–2325.

**A06 — False-looking progress metric [CONFIRMED].** The UI primary progress uses processed/total although processed counts ALL attempted images, including failed, skipped and review. A completed_with_errors run may never process successfully any image. **Modify:** separate **discovered / eligible / attempted / fully analyzed / organized / deferred / skipped / review / failed**; show stage, elapsed time, last productive completion, image and provider; color failures and completion accurately. Expose successful output records, not just counter movement. **Evidence:** SetupWorkers.kt:286–346; Screens.kt:2587–2695.

**A07 — No end-to-end proof that required AI results are correct and persisted [UNVERIFIED].** Real stages exist: OCR, NSFW classification, embedding generation, aesthetic scoring, plus one Qwen-VL structured semantic pass feeding tags/character resolution and organization. v2.0.16 validated a real probe, but the 18 subsequent images were skipped and no full output was independently checked. **Modify:** golden image set and verification API for per-stage real outputs, actual model IDs/versions, raw/normalized outputs, embedding dimension, classification confidence, Qwen structured JSON, Fusion subject/canonical tags, persisted profile and destination. Reject incomplete results; no dummy outputs or silent stages. **Evidence:** StandaloneRuntime.kt:58–67, 1173–1464; AiWorkflowCoordinator.kt:23–292; issue #23.

**A08 — Review queue collapses independent problems for a file [CONFIRMED schema defect].** review_items.image_uri is UNIQUE, and FusionResolutionStore.queueReview updates by image_uri before inserting. A runtime error, possible duplicate, character ambiguity and organization failure on the same image can overwrite one another, losing distinct unresolved reasons. **Modify:** stable review IDs with uniqueness per image + review type + issue identity, independent statuses/corrections, append-only history and migrations without losing existing reviews. **Evidence:** LocalDatabase.kt:189–201; FusionResolutionStore.kt:560–604.

**A09 — Automated organization needs crash recovery and cloud write capability control [HIGH risk].** Current relocation verifies destination and updates the DB before deleting source; this corrects an older unsafe move. Nevertheless, a process death between verified copy and DB transaction can strand copies, and between DB commit/source deletion can leave untracked duplicates; there is no durable filesystem move journal. Read-only Rounder cannot create destination folders and cross-provider copy/move in RoutingStorageProvider is unsupported. **Modify:** explicit capability/read-only checks, user-approved writable destination, durable prepare/copy/hash/commit/cleanup journal, reconciliation and undo; never attempt a cloud write just because a read source was indexed. **Evidence:** StandaloneRuntime.kt:1641–1712, 1715–1940; TeraBoxIntegration.kt:566–607.

## Priority 1 — major throughput and quality corrections

**B01 — PaddleOCR recreates ONNX sessions for each text box [CONFIRMED severe performance defect].** OnnxRuntimeClient.runDetailed constructs OrtEnvironment session and closes it after each call. PaddleOcrRuntime executes detection once and then calls it again for **every recognized crop**. It also rereads the ~18,383-entry dictionary on each image. **Modify:** persistent bounded detector/recognizer OrtSession pool with safe reuse; read dictionary once; batch recognizer crops when compatible; trace session creation, box counts and inference time; recycle source bitmap in finally. **Evidence:** PaddleOcrRuntime.kt:187–277; NativeRuntimeBackends.kt:1176–1216.

**B02 — Redundant full image reads [CONFIRMED].** ImageFingerprinting performs SHA256 full stream read, then dimensions open, then sampled bitmap open; Paddle, Nomic/NSFW and Qwen may decode again. For remote provider each open can be an expensive network operation. **Modify:** one verified bounded staging stream/image per image, reuse decoded reduced image and fingerprint; one full hash when needed; cache bytes keyed by stable source version with integrity checks, bounded disk/memory and cancel-aware I/O. **Evidence:** ImageFingerprinting.kt:21–68, 106–118; StandaloneRuntime.kt:4272–4345; NativeRuntimeBackends.kt:950–1030.

**B03 — Qwen native model remains resident without physical memory eviction [CONFIRMED].** LlamaCppBackend caches its native GGUF/projector handle and explicitly keeps it between images. The separate LocalAiModelLifetimeManager's warm-model timers manage session-cache metadata, not an obvious native Qwen unload; budget reports can therefore miss resident allocations. Android device showed high PSS/swap. **Modify:** explicit native-resident memory accounting, model lifetime ownership, thermal/low-memory eviction, safe serialization with OCR/ONNX, reuse across adjacent images when affordable, and prompt cancellation. Preserve original models. **Evidence:** NativeRuntimeBackends.kt:308–575; LocalAiRuntimePipeline.kt:1725–1788.

**B04 — Reservation budget combines mutable available RAM and logical reservations [CONFIRMED implementation; exact overcommit not measured].** computeReservationBudgetBytes derives a fresh budget from hardwareDetector.detectProfile().availableRamBytes while reserve subtracts reservations.values.sum(); this may double-penalize memory when reserved work has already consumed physical memory. Conversely memory mapping and native caches are not accounted precisely. **Modify:** separate physical free/reclaimable/low-memory signal from modeled concurrent reservations, track actual backend RSS/native/mapped memory, avoid dynamically shrinking budget below active commitments, use thermal/battery-aware thresholds and graceful preemption. **Evidence:** LocalAiRuntimePipeline.kt:1645–1724; AiMemoryReservationPolicy.kt; LocalAiEnvironment.kt:12–43.

**B05 — Probe can monopolize startup for minutes [CONFIRMED device].** A full real-model validation probe ran approximately six minutes before the counter advanced; a single unreadable first-page sample may cause run failure even when later sources are valid. **Modify:** choose a small confirmed-readable local or staged source, validate each installed model once per model/version/backend and invalidate on upgrade, persist probe receipts separately from library progress, report stage timing, and retry/skip only affected provider. Do not eliminate actual inference validation. **Evidence:** SetupWorkers.kt:224–263; StandaloneRuntime.kt:2158–2353.

**B06 — No provider-level failure quarantine [CONFIRMED].** 18 consecutive unreadable images were attempted one after another; skipped does not increment the repeated-failure gate. **Modify:** source/provider-specific failure counts and circuit breakers, early actionable notification for revoked permissions/offline providers, periodic recheck; prevent spending days on one unreachable cloud folder while processing independently accessible images. **Evidence:** SetupWorkers.kt:295–328; StandaloneRuntime.kt:1471–1501.

**B07 — Failed/deferred rows advance cursor [CONFIRMED, partly intentionally handled].** Failure and skipped records remain retry_required and are eligible in later runs; the cursor moves past them in the current pass, and AppViewModel retries from zero only on certain status values. **Modify:** explicit durable retry queue (next_attempt_at, retry_count, reason, provider), revisit deferred jobs independently from the main sequential keyset; never silently exclude unresolved records, even after a successful later segment. **Evidence:** FusionResolutionStore.kt:36–146; SetupWorkers.kt:309–325; AppViewModel.kt:753–769.

**B08 — 8K Qwen context and taxonomy compaction need measurement, not arbitrary truncation [QUALITY risk].** LlamaCppBackend defaults to 8192 context and two CPU threads. QwenPromptBudgetPolicy.compactTaxonomy round-robins entries by category but may drop many valid canonical IDs; inference JSON budget is only 512 generated tokens in the production workflow, which can truncate complex multi-person scenes. **Modify:** benchmark actual tokens, image patches and JSON length; retrieve complete relevant canonical candidate IDs from the immutable database, optionally two-pass bounded retrieval, avoid discarding valid identities merely due prompt order. Benchmark 2/4/etc threads and context on device, no presumed GPU/NPU support. **Evidence:** NativeRuntimeBackends.kt:350–370, 575–699; QwenPromptBudgetPolicy.kt; StandaloneRuntime.kt:1274–1289.

**B09 — No proof aesthetic output reaches permanent image metadata [LIKELY persistence gap].** RuntimeOutputMapper returns aesthetic_score from regression inference, but AiWorkflowCoordinator.applyImageWorkflow visibly writes OCR, caption, embedding, NSFW, normalized context, tags and subjects; it does not explicitly store the aesthetic score in the central image profile. **Modify:** audit all output paths and store required per-stage value/confidence/model version/provenance; verify reload/search/sort by aesthetic score. **Evidence:** NativeRuntimeBackends.kt:1330–1366; AiWorkflowCoordinator.kt:49–68.

**B10 — Per-image output writes are not one atomic semantic transaction [HIGH integrity risk].** AiWorkflowCoordinator writes profile, subject rows, canonical tags, legacy tags and evidence across methods. A crash/failure can leave a mixture of old/new stage results. **Modify:** validate first, then commit a versioned analysis record atomically (or with recoverable transactional journal), preserve manual overrides and provenance, and invalidate dependent indexes only after successful commit. **Evidence:** AiWorkflowCoordinator.kt:49–224; FusionResolutionStore.kt:319–380.

**B11 — Per-image stage telemetry is absent from automation UI [CONFIRMED].** AI execution sessions and progress events exist in SQLite, but the Automation Compose screen polls top-level status every 1.5 seconds and shows only image attempted and generic message. **Modify:** expose current model and stage, input provider, elapsed, ETA based on measured throughput, RAM/swap/thermal, per-stage failures, retry history and a drill-down per-image audit trail without sensitive URI disclosure. **Evidence:** Screens.kt:2570–2710; AppViewModel.kt:719–854; LocalAiManager.kt:1314–1360.

**B12 — Large-library scanner and preview resource policies need instrumentation [RISK].** SAF tree enumeration includes Rounder custom 100-row pagination and waiting loops, but generic listChildren and filename conflict scans use DocumentFile.listFiles, with potential large folder cost. Incremental rescan can call database.optimizeDatabase after a folder walk. **Modify:** provider paged listing, provider-specific timeout/backoff, metadata caching and SQL incremental upserts; keep UI interactive during rescans; measure items/s and remote bytes. **Evidence:** SafStorageProvider.kt:25–204, 210–228, 529–548; StandaloneRuntime.kt:2660–2750.

**B13 — Thumbnail persistence is implemented but not validated across cloud scale [RISK].** PersistentArtworkThumbnails writes verified WEBP into filesDir and SQLite cache, but cloud thumbnail latency, generation backlog, eviction strategy and rapid browsing under large folders are not covered by a real-device stress test. **Modify:** prioritized visible thumbnails, bounded fetch queue and disk cache, progressive placeholders and explicit per-provider errors; avoid full-resolution downloads merely for thumbnail generation. **Evidence:** PersistentArtworkThumbnails.kt; LocalRepository.kt:1150–1287; Screens.kt.

**B14 — Native backend capabilities are more limited than hardware detection suggests [CONFIRMED].** Registered execution backends are ONNX Runtime, TensorFlow Lite and CPU llama.cpp. Qwen runtime declares CPU support, with default two threads; a detected GPU/NPU capability does not mean any model is delegated to it. **Modify:** device-specific backend benchmarks and verified optional delegates for applicable models; measure precision/latency/memory and retain CPU fallback. Do not assume Qualcomm QNN/Vulkan are present or compatible without actual compile/execute proof. **Evidence:** LocalAiManager.kt:1572–1594; NativeRuntimeBackends.kt:350–470; LocalAiEnvironment.kt.

**B15 — Canonical classification quality needs calibrated ground truth [UNVERIFIED].** Parse of Qwen structured JSON now checks required routing fields but provides no per-character calibrated proof; categories and canonical matches can still be wrong even when JSON is syntactically valid. **Modify:** representative labelled evaluation set (multi-character, original character, western/eastern art, cropped faces, NSFW, screenshots), per-series confusion matrix and manual-review thresholds. Never auto-commit low-confidence identity/routing or canonical edits. **Evidence:** NativeRuntimeBackends.kt:738–886; CharacterResolver.kt; ContentTriagePolicy.kt; KnowledgeDatabase.kt.

**B16 — Organization throughput and storage capabilities [RISK].** Every accepted relocation can require target folder existence checks, reserved sequence, full destination copy, source hash, destination hash and original cleanup. Cloud write policies and naming conflicts vary by provider. **Modify:** stage physical organization after verified analysis; batch folder/counter DB operations, cache verified capabilities, let read-only sources remain indexed with a proposed destination, and dry-run preview for first migrations. **Evidence:** StandaloneRuntime.kt:1641–1712, 1715–1940.

**B17 — UI/business-logic maintainability [MAINTENANCE].** Screens.kt is ~5,480 lines, AppViewModel.kt ~2,972 lines and StandaloneRuntime.kt ~4,523 lines. High coupling increases regression risk around navigation, scans and automation. **Modify:** extract tested feature-specific screen/viewmodel/domain modules while preserving public contracts, assets and UI behavior; avoid a disruptive whole-app rewrite.

## Priority 2 — test, operational and UX completion

**C01 — No Android instrumentation suite [CONFIRMED].** No files under app/src/androidTest at snapshot. Existing app/src/test contains 23 Kotlin source files and Python synthetic and static-source tests. CI passes compilation/unit contracts and 300K SQLite simulation but never proves installed native inference or Android JobScheduler behavior. Add Android instrumented WorkManager, SAF fake DocumentsProvider, cloud failure, local model and persisted-output tests; keep a real connected-phone acceptance run for complete inference.

**C02 — Improve CI coverage and release gating.** GitHub android-build workflow currently invokes an explicit subset of Kotlin test classes rather than the entire suite. Run the whole test suite and gate stable release on instrumentation, device smoke/semantics, signing cert fingerprint and no-downgrade update. Do not treat unit/contract test success as evidence of AI output quality.

**C03 — Durable diagnostics and privacy.** Record only hashed/opaque URI IDs, provider authority, stage timing, model version, error type and stack summaries; some current scan logs include raw folder URI. Keep bounded logs with export-on-demand, no cloud auth secrets, user-controlled diagnostics. **Evidence:** StandaloneRuntime.kt:2690–2725; LocalAiManager/LocalAiExecutionHistory.

**C04 — Migration, backup and restore safety.** Preserve existing private Android app files, model imports, Fusion tables, SAF grants and signing identity. Add migration tests for review schema changes, queue state and album/thumbnail caches; in-place upgrade tests from v2.0.15/2.0.16, rollback of failed schema migration, backup of user-authored corrections only with explicit consent.

**C05 — Clarify desktop vs Android functionality.** Repository includes extensive Python engine modules and a separate Kotlin Android runtime. Their mere presence does not prove feature equivalence in the Android APK. Maintain a per-feature contract matrix: native Android implemented; desktop-only; bridge-backed; missing; verified on device. Preserve boundaries from docs/ARCHITECTURE.md and the authoritative Fusion data contract.

**C06 — Full user-facing operational controls.** Provide explicit Run/Pause/Resume/Stop with actual WorkManager state, notification when processing continues, provider reconnect action, independent retry-unreadable/failed selection, per-source filtering, non-destructive organization preview, source-independent settings, clear busy/error states and performance/thermal controls.

**C07 — Image metadata validation.** Required persisted fields should include image source provenance, original URI alias, content hash, image version, OCR text/boxes, visual embeddings, NSFW with confidence, aesthetic score, Qwen caption/context/tags/subjects with confidence, canonical reference version, chosen route and reason, review status, human corrections and timestamp. Distinguish observed from inferred traits and canonical authority.

**C08 — Protection from duplicate reviews, erroneous trash routing and irreversible actions.** Retain reviewed duplicate detection and checksum-verified original preservation introduced in v2.0.12. Keep uncertain promotion/preview, no-character and junk destinations review-gated; never treat model-generated labels as permission to destroy files. Audit every path to StorageProvider.delete. Make all automatic destructive actions default-off pending verified capabilities and user consent.

## Recommended implementation sequence (minimal disruption)

1. **Source correctness and visibility:** typed SAF/remote file errors; Rounder authority recognition; one verified staging file per image; provider-aware readiness; accurate successful/deferred counters; per-stage timings and outputs.
2. **Background and checkpoint reliability:** recover stop reason; durable WorkManager lease/continuation including queue exclusive-lock repair; modern Android execution mode, notification, persisted retry queue.
3. **Real inference throughput:** pool OCR ONNX sessions and dictionary; reduce repeat decodes; dynamic native model memory accounting/eviction; measured Qwen prompt/token/thread optimization, retain all required stages.
4. **Persistence and organization integrity:** atomic per-image outputs; multi-reason review queue migration; non-destructive journaled copy-verify-commit; cloud write caps and review workflows.
5. **Feature/UI quality:** canonical-aware semantic evaluation, full metadata surfaces, responsive cloud gallery, diagnostic panels, migration-safe modular refactoring.
6. **Release gates:** synthetic, instrumentation, real phone, screen-off/background, resume/reboot, low-memory and mixed provider tests; only then signed update.

## Verification gate for next APK

- **G0:** Source health: at least one verified image in each connected provider, exact cause of failures and actionable regrant/reconnect; no losing originals.
- **G1:** 20 controlled representative images complete **all required** real model stages and persist outputs correctly; stage accuracy inspected, not just success status.
- **G2:** 100 then 1,000 mixed local + Rounder/TeraBox images produce audited success/review/deferred counts and reproducible p50/p95 stage timings and memory peaks. No duplicate downstream mutations across retries.
- **G3:** Leave app, switch apps, turn screen off, test charging/idle/thermal and OS job cancellation; verify durable progress and automatic recovery with stop reasons logged. Test pause/resume and process restart; no app-data reset.
- **G4:** Entire initial **14,528-image snapshot** accounted for: successes plus explicit reviewed/retry/blocked sources, with every eligible input eventually retried or flagged; never claim that all attempts equal completed analyses.
- **G5:** Repeat scalable SQL + source pagination tests at **300,017** rows; demonstrate bounded RAM and efficient scans, then baseline projected runtime from measured model inference; do not promise 300K throughput without timings.
- **G6:** Install only a release signed by the permanent v2.0.15/v2.0.16 certificate. Models, artwork, corrections, IDs, user preferences, review history and persisted grants survive.

## Verification ledger and corrections to historical audits

Implemented and preserved: indexed paging, persistent scan/fusion schema, native model loading, task journal, Qwen structured validation, duplicate review without auto-delete, SHA-256 verified copy-before-original-cleanup, early-stage completeness guards, signed APK update continuity.

Source-level defects confirmed: skipped counter semantics, Rounder staging authority mismatch, foreground promotion disabled on modern Android, incomplete background lifecycle, ONNX OCR per-box session churn, mutable memory-admission accounting, single-review-per-URI schema, missing per-stage automation UI, mixed transaction boundaries.

Observed on device: real probe passed after ~6 minutes, 18/18 early attempts skipped, no full analyzed image confirmed, later JobScheduler reported cancellation with cause unknown.

Not verified: Qwen correctness on representative artworks; accuracy/calibration of classifiers; 300K performance; cloud provider permissions and reasons for 18 skips; true unattended long-running operation; all-stage metadata retention; cross-provider write, cloud thumbnails, or exact maximum throughput.
